= Deploy an MCP server

[role="_abstract"]
Before you can use tools in code, you need a tool to call. In this section, you deploy a small *MCP (Model Context Protocol) server* that simulates the IT ticketing system for Oak City General Hospital. Your agent uses this server to read and file tickets.

The MCP server exposes four tools the model can request to use:

- `create_ticket`
- `get_ticket`
- `list_tickets`
- `update_ticket`

The server is pre-seeded with several open tickets you can explore.

After the server is running, a setup job automatically registers it as a connector in OGX so the Playground and your agent can use it.

== Procedure

Deploy the MCP server in one of the following ways:

* *Using the OpenShift CLI*
+
Run the following command:
+
[source,terminal]
----
oc apply -f https://raw.githubusercontent.com/rh-aiservices-bu/hospital-helpdesk/main/setup/mcp-ticketing.yaml
----

* *Using the OpenShift console*
+
--
. In the {productname-short} dashboard, click the application launcher and then select the *OpenShift Console* option.
+
image::6-tools-agents/ds-project-ocp-link.png[OpenShift Console Link, 600]

. In the OpenShift console, click *+* in the navigation bar, and then click *Import YAML*.
+
image::6-tools-agents/ocp-console-add-icon.png[Add resources Icon]

. Click the arrow next to the project name and select your project from the list.
+
image::6-tools-agents/ocp-console-select-project.png[Select a project, 200]

. Copy and paste the following code into the *Import YAML* editor:
+
[.lines_space]
[.console-input]
[source,yaml]
----
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: demo-setup
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: demo-setup-edit
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: edit
subjects:
  - kind: ServiceAccount
    name: demo-setup
---
apiVersion: batch/v1
kind: Job
metadata:
  name: deploy-mcp-ticketing
spec:
  selector: {}
  template:
    spec:
      containers:
        - args:
            - -ec
            - |-
              echo -n 'Deploying MCP ticketing server'
              oc apply -f https://github.com/rh-aiservices-bu/hospital-helpdesk/raw/main/setup/mcp-ticketing-no-sa.yaml
          command:
            - /bin/bash
          image: image-registry.openshift-image-registry.svc:5000/openshift/tools:latest
          imagePullPolicy: IfNotPresent
          name: deploy-mcp-ticketing
      restartPolicy: Never
      serviceAccount: demo-setup
      serviceAccountName: demo-setup
----

. Click *Create*.
--

== Verification

. In the OpenShift console, the `Resources successfully created` message appears, listing:
+
* `demo-setup` (ServiceAccount)
* `demo-setup-edit` (RoleBinding)
* `deploy-mcp-ticketing` (Job)
+
[NOTE]
====
If you already completed the storage setup in xref:1-setup/3-scripted-storage.adoc[1.2.1. Install local object storage with a script], `demo-setup` and `demo-setup-edit` might already exist, and you might see an error for those resources. This is expected. The `deploy-mcp-ticketing` Job still runs correctly.
====
