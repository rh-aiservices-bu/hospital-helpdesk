= Set up tracing with MLflow

[role="_abstract"]
With MLflow tracing, you can collect inputs and responses to the model, as well as any intermediate steps added.
This provides a history of user interactions and model responses, which you can use to test and improve your AI systems.
You send requests to the model with tracing enabled, then view the collected traces in the MLflow UI.

== Prerequisites

- You have deployed a model as described in xref:2-just-a-model/1-model-catalog.adoc[2.1. Deploy a model from the model catalog].
- You have set up a workbench as described in xref:3-move-to-code/2-workbench.adoc[3.2. Create a workbench].

== Procedure

. Return to the workbench and open the notebook called `1_mlflow_request.ipynb`.
This notebook shows how to set up a connection with MLflow and enable tracing to collect information from the requests that the notebook sends.
+
NOTE: You need to enable tracing in all applications you want to appear in the trace. In this case, you enable it from within your Python code.

. Complete the notebook. Then, continue this tutorial.

== Verification

. After the notebook has finished running, return to the OpenShift AI dashboard and select *Develop & train* > *Experiments*.

. Verify that you are in the correct project, and then click the *hospital-helpdesk* experiment.
+
image::4-observability-tracing/click-experiment.png[Click the experiment]

. An overview of your MLflow-tracked requests in this experiment appears. To see the specific traces, select the *Traces* section.
+
image::4-observability-tracing/experiment-overview.png[Experiment overview]

. Your traces from the requests you made in the notebook are listed. There are five in total. Click the top trace to see more details.
+
image::4-observability-tracing/traces.png[Traces]

. A trace provides information such as the system prompt, the input, the output, and any metadata.
The *Details & Timeline* tab shows each step in the trace and how long each step took, which is useful for more complex flows such as agentic workflows.
+
image::4-observability-tracing/trace-info.png[Trace info]

. Optionally, click *Show Assessment* to add *Feedback* and *Expectations* to the trace. You can then add this trace to a dataset by clicking *Add to dataset*. Use the dataset to evaluate other models or system prompts to see whether they behave according to your *Expectations*. This provides a way to build an evaluation dataset from your traces.
+
image::4-observability-tracing/show-assessment.png[Show Assessment]
