= Create a Project

[role="_abstract"]
// Instructions for creating a data science project.

An AI project is what contains many of the tools you will use inside of {productname-short}. You can use projects to collaborate with your teammates, and you can create things such as workbenches (IDEs), pipelines, deploy models, etc. from within your project.

=== Prerequisites

* You have logged in to *{productname-long}*.

=== Procedure

. From the left navigation menu, select *Projects*. This page lists any existing projects that you have access to. You can select an existing project (if any) or create a new one.

. Click *Create project*.
+
NOTE: You can start a Jupyter notebook by clicking the *Start basic workbench* button. However, in that case, it is a one-off Jupyter notebook run in isolation.

. In the *Create project* modal, enter a display name and description.
+
image::1-setup/new-project-form.png[New project form, 600]

. Click *Create*.

=== Verification

Your project opens in the dashboard.

You can click the tabs to view more information about the project components and project access permissions:

image::1-setup/project-new.png[New project]

* *Workbenches* are instances of your development and experimentation environment. They typically contain individual development environments (IDEs), such as JupyterLab, RStudio, and Code Server.

* *Pipelines* are a structured series of processes that collect, process, analyze, and visualize data. With AI pipelines, you can automate the execution of notebooks and Python code. By using pipelines, you can automatically ingest data or fine-tune your models on a schedule without having to manually run them in a workbench.

* *Deployments* for serving a model. It exposes APIs to receive data, run the data through your model, and delivers a result (for example, a poem you asked for).

* *Cluster storage* is a persistent volume that retains the files and data you're working on within a workbench.

* *Connections* points to a data location which you can use for purposes such as configuration parameters and storing models, data, or artifacts.

* *Permissions* define which users and groups can access the project.
