== Introduction

=== Welcome to the Hospital Helpdesk GenAI tutorial

Oak City General Hospital is a large hospital serving thousands of patients and staff. Its IT helpdesk handles hundreds of requests a week. Nurses get locked out of workstations mid-shift. Ward printers jam during prescription runs. Clinical equipment displays cryptic error codes that need fast triage.

Currently, a helpdesk staff member juggles three things at once: a caller on the line, a browser tab with the IT policy document, and a separate ticketing system they have to switch to in order to log the issue. Procedures are buried in documents, ticket fields have to be filled in manually, and institutional knowledge lives in people's heads.

The goal is to build an AI assistant that changes that workflow. One that can look up hospital IT policies and equipment procedures in seconds, raise and update support tickets through a live ticketing system, and answer common questions.

This assistant is for IT helpdesk staff, not patients or clinical staff directly. But because it makes the helpdesk faster and more accurate, the benefits ripple through the whole hospital.

In this {deliverable}, you build this assistant step by step by using {productname-long}. You complete the following tasks:

* Start with a simple conversation with the model.
* Move into code.
* Add observability so that you can see what the model is doing.
* Give the assistant access to hospital policy documents so that it can answer questions accurately.
* Connect the assistant to a live ticketing system so that it can take real actions for helpdesk staff.

== Before you begin

Before you start the {deliverable}, make sure that your environment meets the following requirements:

* You have access to an OpenShift cluster that has {productname-long} installed.
* Your {productname-short} administrator has enabled the following components in the `DataScienceCluster` resource:
** `workbenches`
** `aipipelines`
** `kserve`
** `ogx`
** `mlflowoperator`
** `mcplifecycleoperator`
* Optional: Your cluster has an accelerator, such as an NVIDIA GPU. An accelerator gives the best experience. You can deploy the model on CPU only, but responses are slower.

[IMPORTANT]
====
If your cluster uses self-signed certificates, before you begin the {deliverable}, your {productname-short} administrator must add self-signed certificates for {productname-short} as described in link:https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/latest/html/installing_and_uninstalling_openshift_ai_self-managed/working-with-certificates_certs[Working with certificates^] (Self-Managed).
====

If you are ready, xref:1-setup/index.adoc[start the {deliverable}].
